# Серверный тестовый запуск NextMod

Обновление 12 ноября 2026: для работы с клиентами установлен drop-in `/etc/systemd/system/nextmod-license-bot.service.d/operator.conf` из `deploy/nextmod-license-bot-operator.conf`. Точка входа — `drivemods_bot.server_operator`, принудительно отключающая автоматические отправки ID и списания. Банк и DriveMods обрабатывает владелец; очереди уведомлений и доставки работают на сервере. Предыдущие сведения о первоначальном demo-развёртывании ниже сохранены как история. [Инструкция оператору](operator-guide.md).

Целевой сервер владельца: VDSka, `89.169.7.15`. Фактическое развёртывание считается завершённым только после входа на сервер, установки службы, остановки локального polling-процесса и ответа бота с серверной меткой. Наличие файлов службы в проекте не означает, что бот уже перенесён.

Развёртывание выполнено 7 ноября 2026 года. Служба `nextmod-license-bot.service` активна и включена при загрузке сервера; автоматический перезапуск проверен однократным завершением только её процесса. Ответ `/status` получен в Telegram после остановки локальной копии: «Сервер VDSka», тестовый режим, отправка ID и реальные оплаты отключены. Исходники и зависимости проверены 52 тестами на Windows и 52 тестами на Ubuntu / Python 3.12.16. Существующие приложения сервера продолжают работать.

Обычный `start.cmd` / `start.ps1` проверяет локальную отметку переноса и не запускает вторую копию. Для резервного запуска сначала остановить серверную службу, затем выполнить `powershell -ExecutionPolicy Bypass -File .\start.ps1 -LocalFallback`.

## Подготовленные компоненты

- `python -m drivemods_bot.server_demo` — отдельная точка входа, принудительно сохраняющая `demo`, запрет отправки ID в DriveMods и запрет покупок. Даже переменные `APP_MODE=live` и `STORE_*_ENABLED=true` не включат покупки при таком запуске.
- `deploy/nextmod-license-bot.service` — systemd-служба с отдельным пользователем, запуском при загрузке сервера и перезапуском процесса при завершении.
- `deploy/server.env.example` — только имена настроек. Реальные токен и ID владельца передаются отдельно в закрытый `/etc/nextmod-license-bot.env`.
- `/var/lib/nextmod-license-bot` — постоянные данные, SQLite и локально принятые тестовые файлы.
- `/etc/nextmod-license-bot.hosts` — копия системного hosts с адресом `149.154.167.220 api.telegram.org`, подключённая только внутрь службы. При подготовке DNS сервера выдавал недоступный `149.154.166.110`; HTTPS на выбранном адресе проверен с обычной проверкой сертификата. Системный DNS и `/etc/hosts` не меняются. Если Telegram изменит адреса, этот файл нужно обновить после проверки HTTPS.
- `/status` — команда владельца, показывающая размещение, режим и запреты операций. На сервере должна отображаться метка «Сервер VDSka».
- `python -m scripts.build_server_bundle` — переносимый архив исходников для Linux. `.env`, реальные файлы и сессии браузера в него не попадают.

## Порядок переноса

1. Войти на указанный сервер и проверить ОС, свободную память, диск и существующие службы. Не менять чужие приложения и настройки сети.
2. Подготовить Python 3.12+, отдельную папку `/opt/nextmod-license-bot`, пользователя `nextmod-bot` без интерактивного входа и виртуальное окружение.
3. Передать архив исходников, установить зависимости и записать секреты в `/etc/nextmod-license-bot.env` с правами `0600`.
4. Установить unit-файл, выполнить `systemctl daemon-reload`, проверить конфигурацию. До переключения службу не запускать, чтобы два процесса не читали сообщения одного бота одновременно.
5. При наличии локальных заказов перенести согласованную копию SQLite и связанных файлов, исправив пути для сервера. Данные на ПК сохранять до проверки переноса.
6. Остановить только локальный процесс проекта через `stop.ps1`.
7. Выполнить `systemctl enable --now nextmod-license-bot.service` и проверить активность, автозапуск и журнал.
8. Отправить `/status` и `/orders` в Telegram. Серверная метка и ответы после остановки локального процесса подтверждают независимость от ПК.
9. При сбое запуска остановить серверную копию перед повторным локальным запуском. Не запускать две копии одновременно.

Служба не публикует входящие HTTP-порты: бот получает сообщения через исходящее соединение с Telegram. Автозапуск не является гарантией отсутствия аварий у провайдера; требуется обычное обслуживание сервера.
