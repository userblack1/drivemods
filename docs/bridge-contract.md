# Контракт собственного адаптера DriveMods — ещё не реализован

Это спецификация границы между готовым Telegram-ботом и будущим адаптером реального кабинета. **Эти URL не являются официальным API store.drivemods.org.** Их нельзя подставлять к домену магазина и считать интеграцию готовой. Адаптер нужно реализовать после входа в кабинет и проверки процесса Visa-оплаты. При наличии официального API следует использовать его.

Авторизация собственного адаптера: `Authorization: Bearer <DRIVEMODS_BRIDGE_TOKEN>` по HTTPS. Не передавать в этот секрет Telegram-токен, пароль магазина или номер карты. Файлы и ссылки должны быть доступны только авторизованным запросам. Секреты и содержимое ID-файлов не должны попадать в логи.

## POST /v1/quotes

`multipart/form-data`: `device_id` — исходный файл; `external_reference` — UUID заказа бота. Заголовок `Idempotency-Key: <external_reference>`. Адаптер отправляет ID в DriveMods, проверяет формат/совместимость и возвращает только действительно доступные предложения.

**Загрузка может сама создавать неудаляемый заказ к оплате.** Поэтому этот POST вызывается только после подтверждённой оплаты клиента, никогда при обычном получении файла ботом. Адаптер должен сохранить идентификатор созданной лицензии и связь с UUID даже при обрыве ответа. Бот не повторяет такую загрузку при неопределённом результате. `STORE_UPLOADS_ENABLED=false` запрещает POST ещё до чтения файла и сетевого запроса.

```json
{
  "reference": "quote-123",
  "expires_at": 1794078000,
  "offers": [
    {"plan": "full", "supplier_plan_id": "actual-store-plan-id", "cost_usd_cents": 9000},
    {"plan": "eco", "supplier_plan_id": "actual-store-eco-id", "cost_usd_cents": 6000}
  ]
}
```

`expires_at` — Unix timestamp в секундах. План и цена должны соответствовать конкретному устройству и аккаунту. Не подставлять фиксированные предложения для неподдерживаемого устройства. Счёт покупателю выставляется по локальному тарифу; ответ магазина сверяется после оплаты клиента. Несовпадение пакета/цены блокирует Visa-покупку и требует проверки владельцем, включая вопрос возврата клиенту.

## POST /v1/orders

Заголовок `Idempotency-Key: <external_reference>`.

```json
{
  "external_reference": "UUID-заказа-бота",
  "quote_reference": "quote-123",
  "supplier_plan_id": "actual-store-plan-id",
  "expected_cost_usd_cents": 9000,
  "device_sha256": "SHA256-исходного-ID"
}
```

Адаптер обязан атомарно сохранить соответствие UUID/заказа DriveMods **до оплаты**, исключить повторную покупку по тому же ключу, использовать ранее созданную загрузкой лицензию, сверить пакет/устройство/цену, выполнить отдельный платёж за этот заказ и сохранить полученный файл. Если цена изменилась, платить большую сумму нельзя. Упоминание UUID в комментарии магазина помогает сверке, но само по себе не является гарантией идемпотентности. `STORE_PURCHASES_ENABLED=false` блокирует этот POST на стороне бота.

Разрешённые владельцем пределы итогового списания: FULL — 90 USD, ECO — 60 USD. Они действуют независимо от изменяемых настроек тарифов и должны проверяться также адаптером до оплаты. Валюта — USD, итог с обязательными комиссиями не должен превышать предел. Выбирать все неоплаченные лицензии аккаунта вместо конкретного заказа нельзя. Квитанция исходящей оплаты DriveMods не является подтверждением входящего платежа покупателя. Сохранённая в Link карта не заменяет поддерживаемый DriveMods способ серверного списания.

Ответ `200/201/202`:

```json
{"reference":"actual-store-order-id","status":"pending","action_url":null}
```

Допустимые статусы: `pending` — обработка; `action_required` — владелец должен подтвердить Visa/3DS; `ready` — магазин подтвердил оплату, готова именно запрошенная лицензия; `failed` — нужна проверка заказа/оплаты. `action_url`, если присутствует, — HTTPS-ссылка платёжного провайдера для владельца. Секреты карты и коды не принимаются ботом.

**Сам адаптер пока отсутствует, как и подключение к Visa-провайдеру.** Приведённые примеры описывают требуемый интерфейс, а не подтверждённые ответы DriveMods.

## GET /v1/orders/{reference}

Тот же формат статуса. Чтение не должно создавать новую лицензию или инициировать повторную оплату. Адаптер сверяет фактический статус оплаты у провайдера/в магазине, а не скриншот пользователя.

## GET /v1/orders/by-external-reference/{UUID}

Поиск уже созданного заказа для восстановления после таймаута. `404` только при достоверном отсутствии заказа. Не создавать новый заказ в этом методе. Ответ при существующем заказе — тот же формат статуса.

## GET /v1/orders/{reference}/license

Только для подтверждённого оплаченного заказа со статусом `ready`: `application/octet-stream`, бинарный файл `device.license.bin`. Проверить связь с исходным device ID и выбранным FULL/ECO. Не возвращать исходный ID, HTML кабинета или фиктивную лицензию. Бот проверяет размер, очевидный HTML/JSON с ошибкой и отличие от исходного файла; криптографическую подлинность лицензии подтверждает DriveMods, а не эта проверка.

## Что нужно выяснить в реальном кабинете

1. Авторизация, сессия, наличие API/партнёрского доступа.
2. Действительный запрос загрузки ID и список доступных пакетов.
3. Запрос создания лицензии и уникальный ID заказа/платежа.
4. Visa-провайдер, поддержка сохранённого платёжного токена и необходимость 3DS.
5. Достоверные статусы оплаты, генерации и точная связь скачанного файла с заказом.
6. Возможность сверки без повторного создания/платежа.
