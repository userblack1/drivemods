# Наблюдения в интерфейсе DriveMods

Проверено 7 ноября 2026 во встроенном браузере на авторизованном аккаунте. Исходный ID не выбирался и не передавался. Пустая форма закрыта; список вернулся к прежним 214 записям.

- Список: `https://store.drivemods.org/Record`, параметры React Admin `filter`, `order`, `page`, `perPage`, `sort`.
- Кнопка создания: «Лицензия», переход на `/Record/create`.
- В пустой форме: заголовок «Новая Лицензия», область «ID прибора».
- Файловое поле DOM: `input#idFile`, `name="idFile"`, `type="file"`.
- Комментарий: `input#dealerComment`, `name="dealerComment"`. Подпись «Комментарий», обязательное поле.
- Кнопка «Отмена» возвращает к списку.
- В существующих оплаченных строках видны пакет, ПО, версия кастома, стоимость и «Скачать». Это подтверждает устройство интерфейса, но не даёт официальный API скачивания.
- Разворачивание существующей оплаченной записи показало комментарий дилера; провайдер/форма Visa в этой записи не отображаются.

## Не установлено

Поля и кнопки после выбора реального ID, идентификаторы тарифов, запрос создания лицензии, необходимость 3DS для конкретной карты, точные параметры скачивания и API авторизации. Их нельзя подменять предположениями из скриншотов или собственным контрактом HTTP-клиента.

По объяснению владельца, выбор ID может создавать неудаляемый заказ к оплате. При подготовке этот шаг исключён. Проверка создания новой лицензии отложена до реального нового ID.

## Проверка оплаты существующей лицензии 11 ноября 2026

В авторизованном кабинете уже была одна неоплаченная лицензия `MB-S5WM FULL` с ценой 90 USD. Владелец явно разрешил использовать её, создать платёжную запись и открыть следующий экран. Новый Device ID не загружался и новая лицензия не создавалась.

- Верхняя кнопка «Оплата» открывает `/Record/create` с заголовком «Новая Оплата». Форма содержит таблицу неоплаченных лицензий/услуг, чекбоксы выбора, итог и комментарий.
- После выбора одной существующей лицензии итог составил 90 USD. «Сохранить» создала отдельную запись оплаты с номером заказа вида `DM-…`, статусом «Неоплачено» и одной включённой лицензией. Само сохранение не означало списание.
- «Оплатить» в этой записи открыло диалог «Оплата заказа» со **Stripe Embedded Checkout** в iframe `name="embedded-checkout"` на `js.stripe.com`.
- Форма работает в live-режиме; тестовые данные карты не принимаются. В интерфейсе показаны Visa/Mastercard и Link. Read-only summary Stripe также объявил типы `card` и `apple_pay`; это не подтверждает доступность Apple Pay на каждом устройстве.
- В проверенном счёте доступны исходные 90 USD и альтернативная сумма 8 186,54 KGS с отображённым курсом `1 USD = 90,9616 KGS`. Это историческая котировка конкретного Stripe Checkout, а не согласованный курс для продажи лицензий покупателям.
- Выбрана исходная валюта USD; на кнопке `US 90,00 $` подтверждено `aria-pressed=true`. Поля карты, срок, CVC/CVV, имя и страна заполняются в Stripe. Ввод карты и завершение реального платежа переданы владельцу.
- До передачи владельцу запись оставалась неоплаченной. После самостоятельной оплаты владельцем проверена та же запись: **«Оплачено», 90 USD, одна лицензия/услуга**. Владелец сообщил, что дополнительного подтверждения банка не было и карта не сохранялась. Номера реальной записи оплаты и лицензии сохранены приватно в `data/store-payments/`, без данных карты, CVC, кодов банка и ключей Stripe.

Для этой оплаты сверены **та же** запись по сохранённому номеру `DM-…`, её статус, сумма и количество включённых лицензий. Второй платёж не создавался. При ошибке или обрыве связи в будущих операциях не создавать второй платёж и не повторять списание без сверки. Кнопка скачивания лицензии была доступна в кабинете до оплаты, поэтому наличие скачиваемого файла само по себе не подтверждает расчёт.

Наличие Stripe на сайте не даёт нашему боту доступ к Stripe API продавца. Параметры сессии Checkout не заменяют официальный API/авторизованный адаптер DriveMods. Для этой проверки карта не сохранялась, платёжного метода для автоматических повторных списаний у бота нет. Отсутствие 3DS в одной операции не подтверждает отсутствие проверки в будущих. Согласно [документации Stripe](https://docs.stripe.com/payments/existing-customers?platform=web&ui=stripe-hosted), повторное использование сохранённого метода зависит от настройки Checkout продавцом и согласия клиента. Банк также может потребовать [аутентификацию платежа](https://stripe.com/guides/sca-payment-flows).

## Сохранённая карта Link, 11 ноября 2026

Владелец отдельно разрешил сохранить карту и использовать её для закупки после оплаты клиента. В проверенных меню профиля и кабинета DriveMods отдельного управления сохранёнными картами не найдено. Через официальный [Link Wallet](https://app.link.com/wallet), указанный в [справке Link](https://support.link.com/questions/how-can-i-edit-my-default-payment-method), владелец самостоятельно выполнил вход. В Wallet уже отображалась сохранённая Visa Debit; владелец подтвердил выбор именно этой карты. Приватная запись разрешения содержит только бренд и последние четыре цифры. Карта повторно не добавлялась, новый заказ или платёж не создавался.

Это подтверждает наличие карты в Link. Оно не подтверждает её доступность в следующем Checkout DriveMods, merchant Customer/PaymentMethod или возможность off-session списания нашим сервером. Поддерживаемый способ такой закупки нужно получить у DriveMods.
