# Первый реальный заказ

## Подготовка до выезда

1. **Не загружать старый или тестовый Device ID в DriveMods.** Внешняя загрузка может создавать неудаляемую лицензию к оплате. Пустая форма в кабинете закрыта кнопкой «Отмена»; новых записей при подготовке не создано.
2. Создать своего Telegram-бота через `https://t.me/BotFather`, командой `/newbot`. Указать имя и свободный username с окончанием `bot`. Токен внести только в локальный `.env`, поле `BOT_TOKEN`.
3. Написать `/start` своему боту. Пока процесс бота остановлен, выполнить `.\.venv\Scripts\python.exe -m drivemods_bot identify`. Полученный собственный числовой ID внести в `ADMIN_IDS`.
4. Внести контакт поддержки в `SUPPORT_CONTACT`. Оставить `APP_MODE=demo`, `STORE_UPLOADS_ENABLED=false`, `STORE_PURCHASES_ENABLED=false`.
5. Запустить `check-before-trip.cmd`. Убедиться, что доступны сайт DriveMods, Telegram по токену и нет действующего webhook, мешающего запуску. Команда не отправляет файлы и не списывает деньги.
6. Запустить `start.cmd` и проверить Telegram на синтетическом файле. В деморежиме файл в DriveMods не уходит, счёт в Stars не выставляется, результат — `DEMO-NOT-A-LICENSE.txt`.
7. Оставить авторизованный DriveMods во встроенном браузере для проверки. Если сессия истечёт, войти заново. Это отдельная сессия; автоматически перенести её в серверный адаптер нельзя.
8. На выезд взять компьютер с уже подготовленной рабочей папкой, подключение к интернету и доступ к своей Visa/подтверждению банка. Для другого компьютера есть ZIP с библиотеками; требуется установленный Python 3.12 x64.

## Что уже можно проверить без магазина

`verify.ps1` прогоняет тесты, синтетическую оплату и выдачу. Используется отдельная папка `data/selftest`. Разрешения внешних загрузок/покупок на время проверки принудительно закрыты в процессе, исходный `.env` не меняется.

Изменение исходного ID после оплаты, повторная квитанция, таймаут загрузки, таймаут покупки, повторный запуск и ошибка отправки файла проверяются на имитациях. Создание новой лицензии и Visa-платёж не имитируются на реальном сайте.

## Когда появится новый реальный Device ID

Сохранить исходный файл без изменения содержимого и передать его в текущий чат. Первый реальный тест согласован для FULL с закупочной стоимостью **до 90 USD**. Локальный розничный тариф — 100 USD. ECO: закупка 60 USD, розница 70 USD.

Для локальной подготовки папки заказа без передачи файла в магазин можно выполнить:

```powershell
.\.venv\Scripts\python.exe -m drivemods_bot prepare-order --file "C:\путь\к\новому-device.id.bin" --plan full
```

Команда копирует файл только в `data/field-orders/<ID>/device.id.bin`, сохраняет SHA-256, пакет, цены и уникальный комментарий `TG:<ID> FULL`. Внешних запросов нет. Повторная команда с тем же файлом возвращает ту же папку; с другим пакетом требует сверки.

## Реальная проверка, отложенная до этого заказа

1. Проверить имя и SHA-256 нового файла, выбранный пакет и закупочную сумму.
2. Загрузить именно этот ID в авторизованный кабинет один раз. Сохранить связь с локальным заказом и идентификатор лицензии, который вернёт магазин. Если комментарий доступен до отправки, указать уникальный комментарий из `order.json`.
3. Прочитать фактические варианты FULL/ECO, ограничения устройства и цену. Если FULL стоит больше 90 USD или пакет отличается — остановиться до оплаты.
4. Проверить экран Visa-провайдера. Переход к форме оплаты не считается успешной оплатой. Если требуется подтверждение банка/3-D Secure, его выполняет владелец карты. Номер карты, CVV и коды в чат или настройки бота не записываются.
5. Оплатить один соответствующий заказ. При обрыве связи искать созданную запись/платёж по сохранённому идентификатору; **не загружать ID и не платить повторно вслепую**.
6. Дождаться подтверждённого статуса оплаты и скачивания готовой лицензии по этой записи. Исходный ID и файл лицензии должны различаться; выходное имя — `device.license.bin`.
7. Отправить пользователю готовый файл. Только проверка в автомобиле подтверждает конечный результат русификации/приложений.

Если локальная папка заказа подготовлена, после скачивания можно сохранить финальный файл и номера подтверждений без новых сетевых запросов:

```powershell
.\.venv\Scripts\python.exe -m drivemods_bot complete-order --order-id ЛОКАЛЬНЫЙ_ID --file "C:\путь\к\device.license.bin" --store-reference НОМЕР_ЛИЦЕНЗИИ_МАГАЗИНА --payment-reference НОМЕР_ОПЛАТЫ
```

## Что ещё нельзя обещать заранее

11 ноября 2026 на разрешённой владельцем существующей неоплаченной FULL-лицензии создана одна платёжная запись на 90 USD и открыт Stripe Embedded Checkout. Владелец самостоятельно завершил оплату; та же запись в DriveMods подтвердила «Оплачено», 90 USD и одну включённую лицензию. По сообщению владельца, подтверждения банка не было и карта не сохранялась. [Наблюдения интерфейса](store-observations.md) описывают подтверждённые этапы. Возможность автоматического повторного списания не установлена. Новый Device ID и создание новой лицензии в этом тесте не проверялись.

Адаптер реального DriveMods, фактический выбор пакета после ID, привязка покупки и скачивания к одному заказу требуют проверки на первом реальном ID. Текущий HTTP-клиент реализует **наш собственный контракт**, а не подтверждённый официальный API магазина. Поэтому подготовленный комплект ещё не является сервисом полностью автоматической покупки.

Для публичной продажи цифровых лицензий внутри Telegram дополнительно нужны розничные цены Stars, заполненные условия и поддержка. Расчёт с DriveMods по Visa — отдельная операция, не автоматическое перечисление полученных Stars на карту.
