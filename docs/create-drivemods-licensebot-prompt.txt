ЧТО ЗНАЧИТ «ИДЕНТИЧНЫЙ»
Используй существующий Python-пакет drivemods_bot, а не переписывай бизнес-логику с нуля. 19 основных файлов должны совпадать с reference canonical SHA256, если нет отдельно объяснённого необходимого изменения. Нормализация — UTF-8-sig decode, CRLF→LF, UTF-8 encode. Другой token/ID/username, имя, пути, учётная запись ОС и служба — обязательные различия экземпляра. Старая история заказов и оплаты в новый бот не переносятся.

Оригинал РЕАЛЬНО работает в operator: ID → FULL/ECO → QR → проверка банка оператором → покупка/скачивание DriveMods оператором → загрузка лицензии → отдельное утверждение → отправка клиенту. FULL QR 9000 KGS, ECO 6500 KGS; USD-ориентиры 100/70; закупка максимум 90/60 USD. Автоподтверждения банка, настоящего генератора лицензий и работающей автозакупки у оригинала нет. Не выдавай demo, обработку push или предполагаемый BridgeSupplier за эти интеграции. Не включай live/Stars вместо operator ради видимости готовности.

ЭТАП 1 — ИЗОЛИРОВАННАЯ РАЗРАБОТКА
1. Найди/клонируй проект в отдельную папку, например Документы\Projects\drivemods-licensebot. Существующие папки, изменения, историю и env не перезаписывай. Работай в отдельной ветке task/drivemods-licensebot. Репозиторий публичный по решению владельца; не меняй видимость. GitHub-аккаунт владельца userblack1; входы/пароли первого компьютера не копируй.
2. Проверь Git, Python 3.12 x64; создай отдельную .venv, установи requirements.dev.lock. Создай безопасный локальный .env через scripts/setup_dev_env.py ДО тестов. Проверь внешние переменные процесса и поиск родительских env, чтобы не подхватить token оригинала. Не копируй пустой .env.example целиком как готовую конфигурацию.
3. Выполни pytest, pip check, handoff_audit --history, diff --check и CLI demo. Тестовые операции только во временной БД/папке с синтетическими данными. Демо-файл маркирован, не настоящая лицензия. Не отключай проверки, чтобы получить зелёный результат.

ЭТАП 2 — СОЗДАНИЕ БОТА И ИДЕНТИЧНОСТЬ
4. Создай через BotFather в аккаунте владельца отдельного бота с username ровно DriveMods_licensebot и отображаемым именем DriveMods License. Если username занят — выясни принадлежность и сообщи владельцу; другое имя самовольно не выбирай и оригинал не переименовывай. Для необходимого входа владелец вводит коды/пароли сам.
5. Token сохрани только в новом приватном env/менеджере секретов, не печатай его. Через getMe проверь username case-insensitive, is_bot и новый bot ID !=9227738530. Никогда не используй token @NextModLicenseBot для запуска/identify/updates нового экземпляра. Проверь отсутствие конфликтующего webhook и другого poller нового token; pending updates молча не удаляй.
6. ADMIN_IDS и SUPPORT_CONTACT получи от владельца либо из разрешённых защищённых настроек оригинала без публикации значений. Не делай первого посетителя администратором. Для проверки нового чата владелец должен отправить /start новому боту.
7. Сохрани семь публичных команд оригинала (start/orders/support/paysupport/paymentinfo/terms/myid), все операторские обработчики и callback-форматы. Используй существующий PNG assets/branding/drivemods-licence-v1.png для аватара, если нужен тот же образ. Не используй исключённые JPG/личные референсы.
8. У оригинала getMyDescription/getMyShortDescription устарели и говорят NextMod/demo, хотя production operator. Не включай demo по этому описанию. Новому профилю задай честный текст о FULL/ECO и операторской проверке. scripts/connect_telegram.py умеет привязать владельца по private challenge, но имеет старый username по умолчанию и прописывает старые имя/описания: при его применении явно передай --username DriveMods_licensebot и исправь метаданные только нового бота. Выбор имени и реальный режим не путать.

ЭТАП 3 — ТОЧНОЕ ВОСПРОИЗВЕДЕНИЕ ПОВЕДЕНИЯ
9. Сохрани весь клиентский сценарий спецификации: личные чаты; .id/.bin >0 до 1048576 байт; UUID/локальный SHA256; dedup user_id+SHA256; каталог TTL 1800; выбор FULL/ECO; QR документом; /pay; /orders; /support и защита административных команд.
10. Сохрани QR MBANK: 900000/650000 тыйынов, исходный реальный получатель, тег 54, последний SHA256 checksum, маршрут/тип ELQR, PNG и сохранённые хеши. Не подставляй выдуманный QR. Получи настоящую строку исходного QR защищённо и проверь получателя. Если используется тот же счёт владельца — скопируй разрешённый исходный payload в новый DATA_DIR, не меняя оригинал. QR не является банковским invoice и не подтверждает зачисление.
11. Сохрани /ops, /admin, /status, /device, /paid с кандидатом и отдельной кнопкой, /review, документ /license с отдельным утверждением, /bill для не-QR случаев, /cancelorder, клиентский и операторский /resend. Сохрани точные состояния/транзакции, авторов утверждения, version-token кнопок, уникальность банковских и магазинных ссылок, проверку суммы/валюты/банка, неизменности исходника и файла, ограничения закупки, фильтры PDF/HTML/demo/source-as-license. /refund и live/Stars остаются в коде, но не активируются в operator.
12. Сохрани SQLite WAL, пять таблиц и миграции, events, outbox, FIFO/next_attempt, recover, ограничения повторов и отсутствие повторной закупки при неясном исходе. Бот сам не определяет криптографическую подлинность лицензии: устройство/пакет/оплату поставщику сверяет оператор.
13. У двух независимых БД нет общего dedup банковских платежей. При общем счёте предупреди владельца о необходимости межботовой сверки одной операции; не обещай уже имеющийся общий ledger. Не делай объединённую БД самовольно.
14. Бот прошивок @DriveModsSWBot и Telethon-сессия не входят в этот новый лицензирующий экземпляр. Если нужен также существующий вспомогательный capture-only MBANK-канал уведомлений, клонируй его forwarder отдельно: в исходном коде два ограничения на bot ID 9227738530, их нужно параметризовать проверенным новым ID только в новом экземпляре, добавить тесты и отдельный cursor DB. Не отключай проверку идентичности, не используй старый cursor/token и не превращай уведомления в подтверждение оплаты. Основной operator-бот не должен зависеть от готовности этого дополнительного канала; статус канала честно указать.

ЭТАП 4 — ОТДЕЛЬНЫЙ ЗАПУСК 24/7
15. Для второго ноутбука отдельно проверь SSH: доступ root@89.169.7.15 возможен только после установки его публичного Ed25519-ключа владельцем. Если доступа ещё нет, создай ключ на этом ноутбуке, покажи только .pub/SHA256 и продолжай всю независимую локальную подготовку. Приватные ключи/пароли/Telegram-сессии первого компьютера не копируй. Не обходи ограничения Codex или проверку SSH/TLS.
16. На VDSka подготовь НОВЫЕ, предварительно проверенные на занятость пути:
   service drivemods-license-bot.service
   user/group drivemods-license
   app /opt/drivemods-license-bot
   venv /opt/drivemods-license-bot/.venv
   env /etc/drivemods-license-bot.env (600)
   DATA_DIR /var/lib/drivemods-license-bot

Старые /opt/nextmod-license-bot, /etc/nextmod-license-bot.env, /var/lib/nextmod-license-bot, nextmod-license-bot.service и все службы SW/банка не заменять и не перезапускать. Не запускать старые deploy_* вслепую: они адресуют оригинал, некоторые меняют его .venv.
17. Новая служба прямо запускает python -m drivemods_bot.server_operator; preflight server_operator --check. Не копируй базовый старый unit без operator drop-in: он запускает server_demo. Отдельные user, venv, DB, locks и только новый token. Сохрани подходящие systemd Restart=always/RestartSec=5, TimeoutStopSec=40, UMask=0077, StateDirectoryMode=0700 и изоляцию путей. Для DNS при необходимости используй отдельный проверенный hosts/drop-in новой службы с проверкой TLS; глобальную сеть сервера не меняй. Новый публичный порт для polling не нужен.

19. Первичный новый запуск разрешён этой задачей после проверок. Запускай только новую службу. До/после сравни PID, active state, код/настройки оригинала и убедись, что он продолжает работать. Не обещай нулевой простой любой будущей смены Python-кода, но при создании отдельного экземпляра оригинал перезапускать не требуется.
