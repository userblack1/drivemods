# Покупка собственной картой через Stripe Checkout

`BrowserStripeExecutor` — обычный покупательский процесс через официальный
Stripe.js и Embedded Checkout. Он не получает секретный ключ продавца,
не имитирует подтверждённую оплату и не требует сбора карт клиентов.
Используется только отдельно разрешённая собственная Visa владельца с
последними цифрами 6994, FULL ровно $90 или ECO ровно $60.

Карта поступает из `OwnerCardVault`: зашифрованное хранилище и отдельный
закрытый ключ находятся вне Git и ZIP. Сохранение карты выполняется только
после явного согласия владельца. Номер, CVC, имя и срок не записываются в
журнал операций, сообщения, трассировки, HAR или скриншоты. Контекст браузера
временный; постоянный профиль не создаётся. После попытки ссылки на поля
карты очищаются по мере возможностей Python; это не обещание физического
обнуления всех копий строк в памяти.

Конструктор и `configured` не создают файлы и не запускают браузер.
Сам исполнитель не вызывает `load()` до начала разрешённой попытки;
проверка `vault.configured` может кратковременно расшифровать и очистить
карту, чтобы подтвердить исправность хранилища. Нужны настоящий vault, live publishable key Stripe и
установленный Playwright с явно заданным Chromium executable.
`automatic_payment_ready` дополнительно требует успешного `probe_runtime()`:
явной проверки запуска пустой страницы без карты и платёжного запроса.
Обычный `--check` этого не делает; отдельная проверка браузера должна быть
явно запрошена. `PWDEBUG` и `DEBUG=pw:…` блокируют исполнителя, чтобы
отладочный вывод Playwright не записал введённые значения.

`start()` принимает только доверенный `CheckoutSession`, созданный магазином
по проверенному HTTPS-соединению для точного собственного заказа. Проверяются
invoice/payment/session ID, USD, сумма, пакет и карта. Клиентский секрет
должен принадлежать этой же сессии. Страница формируется в памяти и подключает
`https://js.stripe.com/v3/`; перед вводом карты проверяется HTTPS-origin
платёжного iframe: `checkout.stripe.com` либо точный `js.stripe.com`
с путём `/v3/embedded-checkout-inner-<hash>.html`. Другие origin или
страницы js.stripe.com отклоняются.

Исполнитель использует только наблюдавшиеся поля `#cardNumber`, `#cardExpiry`,
`#cardCvc`, `#billingName` внутри `Embedded checkout`. Он не подбирает неизвестные
элементы. Наблюдавшийся native select `#billingCountry` явно устанавливается
в `KG` для карты владельца O!Bank; выбранное значение проверяется ещё раз
перед оплатой. Страна по IP сервера не используется как подтверждение.
Отсутствующий/неизвестный виджет или сохранение другого значения блокируют
нажатие. Наблюдавшийся переключатель USD имеет доступное имя вида
`US $90.00` или `US 90,00 $`; для ECO проверяется $60. Перед оплатой
он должен быть выбран с точной суммой, а вариант KGS — выключен. Имя
читается из accessibility snapshot, поскольку обозначение US может
поступать из alt-текста флага и отсутствовать в обычном textContent.
Такой отдельный проверенный выбор суммы допускает настоящую кнопку
`Pay`/`Оплатить` без суммы. Если адаптивных валютных переключателей нет,
кнопка обязана содержать точную сумму, а форма — явное USD/US$.
Сумма проверяется повторно после заполнения карты. Неизвестная валюта, комиссия сверх лимита,
другая сумма, подписка или изменившийся интерфейс останавливают покупку.

Журнал SQLite резервирует попытку до запуска формы, а состояние `submitting`
записывается до единственного нажатия оплаты. Один ключ заказа и одна
checkout-сессия не используются повторно, в том числе после таймаута или
перезапуска. Неопределённый результат требует чтения состояния магазина;
повторное списание не выполняется. Старый несовместимый журнал не сбрасывается
автоматически.

Успешный `onComplete` возвращает только `pending`. Готовность оплаченной
лицензии по-прежнему подтверждается собственными записями DriveMods и точной
привязкой устройства/пакета. 3DS, банковское подтверждение, отказ карты или
неопределённый результат возвращают `action_required` либо безопасную ошибку.
Исполнитель не читает и не вводит OTP; проверка банка может потребовать
участия владельца, поэтому круглосуточная работа без единого подтверждения
банка не гарантируется.

Контракт UI и работоспособность настоящего полного заказа должны быть
проверены отдельно. Тесты `tests/test_stripe_browser.py` используют только
явные автономные browser fixtures и синтетическую карту. Они проверяют
ограничения суммы/валюты, origin iframe, запрет повторного клика и повторного
использования сессии, очистку ссылок на карту, 3DS и 10 отдельных заказов.
Эти тесты не являются фактом настоящей покупки.

Основы интеграции: [официальный Embedded Checkout](https://docs.stripe.com/checkout/embedded/quickstart)
и [Adaptive Pricing](https://docs.stripe.com/payments/checkout/localize-prices).

## Проверенный статус на 25 ноября 2026

Код исполнителя реализован; на VPS пройден запуск пустого sandbox Chromium. Владелец дал согласие, encrypted vault и отдельный ключ сохранены локально. Новая служба на момент подготовки ещё неактивна; новый реальный E2E с Device ID не завершён. Первый оплаченный заказ должен пройти fail-closed сверку полных SHA-маркеров и точных собственных Record до карты. Письмо поставщику отклонено и не отправлялось; обычному покупательскому UI merchant API не обязателен. Эти факты не означают, что банк никогда не запросит 3DS.
