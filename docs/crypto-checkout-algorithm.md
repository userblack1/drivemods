# Криптоплатёж → закупка DriveMods → доставка

Состояние на 24 ноября 2026: реализован и проверен **изолированный прототип**, а не включённая автоматическая продажа. Действующие службы Telegram не изменены. Реальная автоматическая закупка DriveMods пока не подключена.

## Подтверждённые исходные данные

- Владелец предоставил публичный адрес Binance в сети TRON и подтвердил ввод сумм с двумя десятичными знаками в «Мой О!». Полный адрес сохранён только в исключённом локальном файле.
- Контрольная сумма адреса верна. Удалось прочитать высоту solidified-блока TRON и историю USDT за сутки; в момент проверки входящих переводов за этот период не было. Это не подтверждает владение адресом, состояние баланса Binance или совершённую оплату клиента.
- Авторизация в кабинете DriveMods действует. Проверены список из 255 записей, существующая оплаченная запись на 60 USD и форма создания оплаты. В ней одна неоплаченная лицензия FULL за 90 USD; исходно выбрано 0 строк, итог 0. Форма закрыта без сохранения. Новые лицензии/платежи не создавались, Visa не списывалась.
- Интерфейс DriveMods показывает возможность скачать файл и до оплаты. Поэтому кнопка скачивания сама по себе не подтверждает оплату.

## Алгоритм

1. Получить ID устройства, сохранить исходный файл и SHA256. Выдать UUID заказа. До подтверждения оплаты клиента файл не передаётся в DriveMods.
2. Зафиксировать пакет, адрес, сеть TRON mainnet, контракт USDT и точную целочисленную сумму в миллионных долях USDT. Базовые демонстрационные цены: FULL 100 USDT, ECO 70 USDT. Это отдельное предложение, не фиксированные 9000/6500 сомов; перед запуском владелец утверждает цены.
3. Предпочтительный способ: отдельный принадлежащий владельцу адрес на каждый заказ, цена ровно 100/70 USDT. Ключи для расходования средств серверу не нужны. Адреса никогда не выдаются повторно. Для кошелька Binance нельзя получить новые адреса простым изменением последней буквы или вывести их из одного публичного адреса.
4. Для предоставленного общего адреса предусмотрен **явно разрешаемый** вариант уникальных сумм: FULL 100.01–100.99, ECO 70.01–70.99 USDT. Сумма показывается до оплаты целиком. Не включать скрытно. В прототипе каждая комбинация адрес/сумма используется только один раз за всё время, включая истёкшие счета. Это ограничение в 99 счетов на пакет для одного адреса, а не бесконечный production-процесс. По исчерпании система останавливает выставление счетов. Для постоянной работы нужны дополнительные адреса или провайдер с уникальным invoice ID. Повторная выдача суммы через 30 минут не решает проблему позднего платежа.
5. Получить кандидатов перевода через TronGrid с пагинацией. Затем прочитать именно `/walletsolidity/gettransactioninfobyid`. Требовать совпадения TXID, успешного исполнения, настоящего контракта USDT, события Transfer, адреса, точной суммы, блока и времени заказа. Подтверждение отправки, скриншот, символ USDT у стороннего токена и неподтверждённая квитанция недостаточны.
6. Сохранить пару TXID/log_index и хеш квитанции атомарно. Одну пару нельзя зачесть дважды. Недоплата, неподходящий адрес и старые переводы не подтверждают заказ. Просроченная оплата требует отдельного разрешения, не переносится другому клиенту.
7. Для Binance дополнительно проверить историю депозитов **с доступом только на чтение**: та же сеть TRX, актив USDT, TXID, адрес, сумма; status=1, без незавершённого Travel Rule. Status=6 (зачислен, но вывод недоступен), 0 и 8 не разрешают закупку. Без этих реквизитов прототип различает перевод на адрес и подтверждение зачисления в аккаунт.
8. Только после обоих подтверждений атомарно занять заказ на закупку. Передать ID в DriveMods один раз, записать связь UUID/ID лицензии/оплаты. Сверить устройство, пакет, валюту USD и итог: FULL 90 USD / ECO 60 USD, включая обязательные сборы. Другие неоплаченные лицензии аккаунта в платёж не включать.
9. До нажатия оплаты сохранить `charging`. Использовать разрешённый владельцем способ Visa в кабинете магазина. После таймаута сначала читать статус конкретного платежа, не нажимать оплату повторно. Требование 3DS переводит заказ в `action_required`; подтверждения банка не обходятся. Наличие карты в Link не гарантирует её доступность автономному серверу.
10. После подтверждённого `paid` и номера оплаты поставщика скачать файл для нужного заказа, проверить формат, размер и отличие от исходного ID; сохранить SHA256. Это структурная проверка файла, не криптографическая проверка лицензии DriveMods.
11. Отправить клиенту `device.license.bin`, сохранить результат доставки. При сбое повторять доставку из сохранённого файла, а не покупать заново. Потерянный ответ Telegram может привести к повторной отправке файла; гарантии exactly-once для внешней доставки нет.

## Что реализовано

- `crypto_checkout/tron.py`: чтение mainnet, Base58Check, пагинация, строгий разбор solidified-USDT-переводов. Нет подписи/отправки криптовалюты.
- `crypto_checkout/binance.py`: подписанные HMAC-запросы истории депозитов и прав ключа. Разрешено чтение истории депозитов, прав ключа и публичного времени для синхронизации; нет торговли, вывода, переводов или доступа к Visa.
- `crypto_checkout/ledger.py`: отдельная SQLite-база, уникальные счета, атомарное подтверждение, сохранение событий, защита от повторов и смешивания тестовых/реальных данных.
- `crypto_checkout/watcher.py`: сверка поступлений и, при наличии ключа, зачисления Binance. Пропуск RPC/индексатора не продвигает курсор мимо непрочитанных событий.
- `crypto_checkout/observer.py`: отдельное постоянное наблюдение за публичным адресом. Развёрнуто на VDSka 89.169.7.15: `drivemods-crypto-observer.service`, пользователь `drivemods-crypto`, приложение `/opt/drivemods-crypto-observer`, закрытые настройки `/etc/drivemods-crypto-observer.env`, наблюдения `/var/lib/drivemods-crypto-observer/observations.sqlite3`, состояние `/var/lib/drivemods-crypto-observer/health.json`. Использует зависимости окружения нового бота только для чтения: `/opt/drivemods-license-bot/.venv`. Его режим `observe_only` не подтверждает заказы. Состояния/PID/число перезапусков шести прежних служб при установке не изменились.
- `crypto_checkout/fulfillment.py`: автомат состояний закупки/сверки/скачивания/доставки, лимиты Visa, защита от параллельного повторного списания. Реализованы DriveModsStoreAdapter и отдельный BrowserStripeExecutor для обычной покупки собственной картой через Stripe UI. UnconfiguredDriveMods остаётся безопасным вариантом без настроенного подключения; отсутствие данных не подменяется успешной оплатой. Новый настоящий E2E ещё не проверен.
- `crypto_checkout/demo.py`: проверяемая симуляция на настоящем парсере и автомате состояний. Платёжные и магазинные ответы синтетические, деньги не переводятся, выдаются только явно обозначенные тестовые TXT-файлы.

## Запуск проверки

В подготовленном Python-окружении проекта:

```powershell
.venv/Scripts/python.exe -m pytest tests/test_crypto_checkout.py -q
.venv/Scripts/python.exe -m crypto_checkout demo --out data/crypto-checkout/demo
.venv/Scripts/python.exe -m crypto_checkout inspect --address ПУБЛИЧНЫЙ_TRON_АДРЕС --out data/crypto-checkout/wallet-inspection.json
```

Адрес публичный, но связан с финансами владельца: не включайте его в общие отчёты, Git или скриншоты. Секреты храните в исключённом `.crypto.env` с ограниченными правами, не в аргументах команд. Перед использованием чтения Binance сначала проверяются права ключа; торговля/вывод/переводы должны быть выключены. Ограничьте ключ IP сервера, если доступна эта настройка.

Прогон 24 ноября 2026: десять клиентов, десять разных тестовых счетов, десять тестовых закупок и десять доставленных TXT; десять повторных уведомлений проигнорированы. Настоящих платежей, списаний и лицензий — ноль. Отдельно проверены ложные токены, недоплата, неверный адрес, старый/поздний перевод, параллельные обработчики, цена/пакет/устройство поставщика, обрыв ответа оплаты, требование 3DS и сбой доставки. Финальный полный локальный набор: **423 теста прошли**, включая **40 новых проверок**. Интерактивная схема сверена с JSON фактического тестового прогона; выбор клиента/этапа проверен в DOM, реальная банковская операция в схеме не выполняется.

## Что требуется до реального запуска

1. Подтверждённые правила цены/разделения счетов: для текущего Binance-адреса уникальные суммы ограничены; для постоянной работы нужен масштабируемый способ уникальных реквизитов.
2. Ключ Binance только для чтения, если требуется подтверждать именно доступное зачисление на Binance. Он не даёт боту права вывести USDT на Visa.
3. Рабочий адаптер авторизованного кабинета DriveMods с проверенными действиями загрузки ID, выбора пакета, создания одной оплаты, использования разрешённой Visa, сверки и скачивания. Изучение интерфейса и сохранённая карта не заменяют эту реализацию.
4. Отдельная проверка одного настоящего заказа после настройки. До неё не принимать реальные деньги через прототип и не включать списания.
5. Оборотный остаток USD на Visa: поступившие USDT не превращаются автоматически в доллары на карте. Обмен/вывод — отдельный процесс с возможными расходами.
6. Выбрать допустимый канал продаж: цифровые товары внутри Telegram требуют Stars. Прямой криптоприём нельзя представлять как разрешённую замену Stars внутри бота. Production Telegram пока остаётся в операторском режиме.

## Состояние на 25 ноября 2026

Покупательский исполнитель реализован, sandbox Chromium на VPS проверен; владелец согласовал и локально сохранил encrypted vault собственной карты. Новая служба при подготовке ещё неактивна. Первый реальный заказ допускается только с проверкой сохранённых магазином полных SHA-маркеров и точных собственных Record до нажатия оплаты; новый Device ID и полный живой E2E ещё не проверялись. Merchant API и письмо поставщику для обычной покупки собственной картой не обязательны. Письмо отклонено владельцем и не отправлялось. 3DS и неизвестный результат удерживают очередь без повторного списания.

Один общий адрес даёт **99 сумм на пакет, 198 за всё время**, а не 198 одновременно. Суммы истёкших счетов также заняты навсегда. После исчерпания новые счета блокируются; для масштабирования нужна другая схема уникальных платёжных реквизитов.
